 Java 8 + JDBC Assignment

Customer Order & Invoice Management System

1. Business Scenario

You are required to develop a Customer Order & Invoice Management System for a simple e-commerce application.

The application allows customers to purchase products available in the system. A customer can place multiple orders, and each order is associated with one product and a quantity.

The system must maintain customer, product, and order information in a MySQL database.

The application must be developed using:

- Standard Java 8
- Object-Oriented Programming
- Java Collections
- Java 8 Functional Programming
- Java 8 Stream API
- JDBC
- MySQL


The application must be implemented using pure JDBC for database access.

The following technologies/frameworks must NOT be used:

- Hibernate
- JPA
- Spring
- Spring Boot
- Spring Data
- Any ORM framework

---

The system contains three primary entities:


Customer

A customer can place multiple orders.

Each order belongs to one customer and refers to one product.
	
A product can be associated with multiple orders.

 3. Customer

Create a `Customer` class representing a customer of the application.

The Customer must contain the following information:

| Field      | Description                                  |
| ---------- | -------------------------------------------- |
| customerId | Unique identification number of the customer |
| password   | Customer login password                      |
| email      | Customer's unique email address              |
| credit     | Available credit amount of the customer      |

Functional Requirements

1. The system must allow creation of a new customer.
2. `customerId` must be unique.
3. Email address must be unique.
4. Password must not be empty.
5. Credit cannot be negative.
6. A customer must have sufficient credit to place an order.
7. The system must allow searching for a customer using the customer ID.
8. The system must allow searching for a customer using email and password.
9. If a customer cannot be found, the application should handle the situation appropriately without causing a `NullPointerException`.

---

 4. Product

Create a `Product` class representing a product available for purchase.

The Product must contain:

| Field     | Description                         |
| --------- | ----------------------------------- |
| productNo | Unique product number               |
| price     | Price of the product                |
| stock     | Number of units currently available |

Functional Requirements

1. The system must allow creation of products.
2. `productNo` must be unique.
3. Product price must be greater than zero.
4. Product stock cannot be negative.
5. The system must allow searching for a product using the product number.
6. The system must allow displaying all available products.
7. The system must allow displaying products that are currently in stock.
8. The system must allow displaying products based on a specified price range.
9. The system must allow displaying products having stock greater than a specified quantity.

---

 5. Order

Create an `Order` class representing a purchase made by a customer.

The Order must contain:

| Field      | Description                        |
| ---------- | ---------------------------------- |
| orderNo    | Unique order number                |
| orderDate  | Date on which the order was placed |
| customerId | Customer who placed the order      |
| productNo  | Product being purchased            |
| quantity   | Number of units purchased          |

The order date must use the Java 8 Date/Time API.

Use:

java.time.LocalDate


instead of the older `java.util.Date`.

Password

 8. Place an Order

A logged-in customer should be able to place an order.

The customer must provide:


Product Number
Quantity


For example:


Customer ID : 101
Product No  : P101
Quantity    : 2


The system must perform the following validations before creating the order.

Validation 1 — Customer

Verify that the customer exists.

Validation 2 — Product

Verify that the requested product exists.

Validation 3 — Quantity

Quantity must be greater than zero.

Validation 4 — Stock

Verify that sufficient stock is available.

For example:


Available Stock : 10
Requested       : 4

Order allowed.


But:


Available Stock : 3
Requested       : 5

Order rejected.


Validation 5 — Order Amount

Calculate:


Order Amount = Product Price × Quantity


Validation 6 — Customer Credit

Verify that the customer's available credit is sufficient to purchase the product.

For example:


Product Price     = ₹50,000
Quantity          = 2

Order Amount      = ₹1,00,000

Customer Credit   = ₹1,50,000

Order allowed.


If the customer's credit is insufficient, the order must be rejected.

---

 9. Order Processing

When an order is successfully placed, the system must perform all of the following operations:

1. Create a new order.
2. Reduce the product stock.
3. Reduce the customer's available credit.

For example:


Before Order

Product Stock       = 20
Customer Credit     = ₹1,00,000

Order Quantity      = 3
Product Price       = ₹10,000


After Order

Product Stock       = 17
Customer Credit     = ₹70,000


The database must not be left in an inconsistent state.

 11. Generate Order Details

For invoice generation, the application needs more information than what is stored directly in the Order object.

For each order, the application should determine:

Order Date
Customer
Product
Product Price
Quantity
Order Amount


The order amount must be calculated as:


Order Amount = Product Price × Quantity


The application should create an appropriate Java object to represent these combined details.

 13. Invoice Requirements

The invoice generation functionality must support:

13.1 Individual Order Amount

For every order:


Product Price × Quantity


must be calculated.

13.2 Total Invoice Amount

Calculate the sum of all order amounts belonging to the customer.

13.3 Highest Value Order

Display the order having the highest order amount.

Example:


Highest Order:
Order No : 1005
Amount   : ₹1,50,000


13.4 Lowest Value Order

Display the order having the lowest order amount.

13.5 Number of Orders

Display the total number of orders placed by the customer.
